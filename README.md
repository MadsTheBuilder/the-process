# The Process: Operation Red Balloon

This repo is the pre-production and post-production workspace for **Operation Red Balloon**. The film is a Hinglish explainer series set in Mirzapur. A child goes missing at a mela, and the case is used to walk up the Uttar Pradesh police hierarchy, from the Mela Chowki constable to the DGP in Lucknow.

The repo records the process, not only the output. It goes from a script and reference images to an animated storyboard, then to a 3D blockout, then to a finished edit built on the presenter's recorded voiceover. Every step is code: HTML compositions rendered with [HyperFrames](https://github.com/heygen-com/hyperframes), a Python build script, a Blender scene script, and local Whisper transcription.

```
Script V11 (PDF) + Visual Reference Book (PDF) + Rederence-images/
        │
        ▼
 1. Animatic storyboards (HyperFrames, SVG stick figures)
    red-balloon-part1/      Part 1, 26 shots, 1:42
    red-balloon-part2-3/    Parts 2–3, 46 shots, 5:28
        │
        ▼

        ▼
 4. Final storytime edit (HyperFrames, generated by build.py)

```

## 1. Animatic storyboards

**Folders:** `red-balloon-part1/`, `red-balloon-part2-3/`

### What it does

Each folder is one HyperFrames project that renders to a 1920×1080, 25 fps MP4. Every shot is drawn live in SVG with primitive shapes and stick figures. No image generation is used. Each frame shows:

- **Panel (1216×684):** the scene itself. It includes the environment (stalls, bulb strings, ferris wheel, chowki, desk), the characters, lighting arrows (3000K amber key and 6500K cool fill), rust focus rings, and the camera move.
- **Panel overlays:** a HUD row with lens, camera height and move, and a top-down camera plan showing field of view, subjects and key light.
- **Side card:** camera, lighting, environment and character notes, a direction note, and two reference thumbnails (one from `Rederence-images/`, one board crop from the reference book).
- **VO line:** the Hinglish narration with a speaker tag (VO, FATHER, SELLER…) and an English translation.
- **Timeline strip:** sequence bars and shot cells with a moving playhead.

Every setup is covered as **wide → medium → close**.

### How it works

Everything lives in one `index.html` per project:

1. **Drawing helpers** build SVG strings. `fig` and `bust` draw figures, with options such as `sari`, `gamchha`, `specs`, `sweat`, `ring` and `key`. `stall`, `bulbs`, `ferris`, `lane`, `crowd` and `balloonBunch` draw the environment. `arrow` and `label` draw annotations. `nset`, `hostDesk`, `ladder` and `star` draw the narrator set.
2. **`scenes.sXX()`** holds one function per shot, returning that shot's SVG.
3. **`SHOTS`** is the data array: duration, side-card text, references, VO line and speaker per shot.
4. **Timing is data-driven.** Shot start times are summed from each `dur` in `SHOTS`. The strip, sequence bars, timecode and total all follow from that. Each shot's `<section class="clip shot">` must carry matching `data-start` and `data-duration`. If they disagree, the script throws and the render fails. That is deliberate.
5. **One GSAP timeline** animates everything, with every tween placed at `A.sXX + offset`.

### Rules the boards follow (from the reference book)

- Every kidnapping claim stays attached to the balloon seller. There is no flashback, no van and no kidnappers on screen, and the seller shares the parents' light so he is never lit as a villain.
- Ravi stays level with the parents, with no desk barrier between them. There is no refusal, bribe or delay at the desk, and no readable FIR text.
- Khan is voice only. Rank and post labels and insignia go on only as post composites, with no invented officers.

### Commands

Run these from inside a project folder:

```bash
npx --yes hyperframes@0.8.91 check                                  # lint + layout, must be 0 errors
npx --yes hyperframes@0.8.91 snapshot --at 8,30.9,54 --no-end       # check stills + contact sheet in snapshots/
npx --yes hyperframes@0.8.91 render -o renders/<name>.mp4 --fps 25  # full render
npx --yes hyperframes@0.8.91 preview --background                   # Studio at http://localhost:3002
```

`BRIEF.md` in each project is the HyperFrames brief: workflow, intent, assets and notes. `AGENTS.md` and `CLAUDE.md` are the authoring rules generated by `hyperframes init`.

## 2. 3D blockout

**Folder:** `part1-storytime/blockout/`

### What it does

This step rebuilds the Part 1 animatic as a grey-box 3D scene in Blender, at real scale and with the same 27 cuts and 102.3 s runtime. It tests whether the storyboard's framing actually works in space.

### How it works

| File | Role |
|---|---|
| `scene_kit.py` | Small Blender helper library: easing and interpolation (`seg`, `lerp`, `ease`), camera aiming (`look_quat`), materials (`mat`), primitives (`add_box`, `empty`, `light`), collections, keyframing and markers |
| `scene.py` | Builds the whole world and bakes the animation. The mela lane runs along +X from the gate (x=10) to the clock tower (x=150). Stalls, the jalebi counter, the balloon seller's spot, the ferris wheel and a separate narrator room are placed from constants. `SHOTS` (camera per shot) and `stage()` (cast positions per shot) mirror the animatic's `SHOTS` table. One camera cuts per shot, and every frame is baked from that data |
| `shot_frames/` | First and last frame of every shot, used for review |
| `shot 1 story to 3d review.md` | Shot-by-shot comparison of storyboard and blockout |

Build it with the create-3d-scene Blender wrapper, which runs Blender in an isolated user dir:

```bash
~/.claude/skills/create-3d-scene/scripts/blender.sh -P scene.py -- <abs-path>/red_balloon_p1.blend
```

### Review result

The overall match is **about 44%**. Durations and cut points match exactly. Framing drifts, mostly because cameras sit at right angles to the lane instead of looking down it. Other gaps: wide shots have no crowd, several set pieces are missing, and the warm/cool light split is absent. The review lists a fix per shot. The first pass is to re-aim 1A, 1B, 4C, 5A and 5E onto the lane axis and to swap the father and mother in 5G.

## 3. Voiceover transcription

**Folder:** `part1-storytime/work/`

### What it does

This step turns the presenter's recorded Hinglish voiceover into timed phrases, so the captions and the cuts can lock to the real delivery.

### How it works

| File | Role |
|---|---|
| `asr.py` | Runs faster-whisper `large-v3` on CUDA over the whole VO (`language="hi"`, word timestamps, VAD) and writes `transcript.json` with segment and word timings |
| `chunks.py` | A more reliable second pass. It uses `ffmpeg silencedetect` to find pauses, cuts the audio at the midpoint of each pause, and transcribes each chunk on its own. That gives clean phrase boundaries for captions. Output: `p1_chunks.json` |
| `transcript.json`, `p1.json`, `p1_chunks.json` | Transcription results |
| `*.jpg` | Frame grabs used to check the edit |

Both scripts add the pip-installed NVIDIA cuBLAS/cuDNN `bin` folders to the DLL path so faster-whisper finds the GPU on Windows.

## 4. Final storytime edit

**Folder:** `part1-storytime/`

### What it does

This is the finished Part 1 video (1:54): the presenter's voice over animated b-roll, with the presenter on camera at key moments. It includes phrase captions, chapter tags, witness-statement cards, a sound bed and SFX.

### How it works

`index.html` is **generated**. Do not edit it by hand. Edit `build.py` or `template.html.tpl` and run:

```bash
python build.py          # rewrites index.html
npx --yes hyperframes@0.8.91 render -o renders/operation-red-balloon-part1-storytime.mp4 --fps 25
```

`build.py` does the following:

1. **Maps recording time to output time.** The recording skips the witness dialogue, so `T(rec)` splices in two silent inserts: 4 s after rec 42.88 and 12 s after rec 45.87. It also adds a 3.5 s cold open (the map zoom) and a 3 s tail. Every other timing in the file goes through `T()`.
2. **Captions (`CAPS`).** Phrase-level captions come from the transcription. `*word*` marks a highlighted word.
3. **Witness statements (`STMT`).** Typed-out quote cards for the father's question and the seller's answer, shown during the silent inserts with typing SFX.
4. **Picture windows.** `BROLL` sets when the b-roll plays full-frame. `FACE` sets when the host is full-frame, with the rank ladder composited beside them. `PIP` sets when the host sits in a circular picture-in-picture bubble. `media_at()` maps output time back to the source recording so the facecam stays in lip sync.
5. **Chapters.** Tags such as "CASE 01 · MIRZAPUR MELA · 19:00", "19:10 · THE SEARCH" and "19:15 · THE WITNESS".
6. **Audio.** VO clips, a drone bed with volume automation that swells under the inserts and ducks under speech, and SFX. The SFX go on tracks by greedy lane-packing so no two overlap on one track.
7. It fills `template.html.tpl` with all of these clips and writes `index.html`.

`broll/` is a separate HyperFrames project that renders the clean b-roll (`broll-clean.mp4`), which is the animatic panels retimed to the recorded VO. The main edit uses that render as its bottom video track.

`assets/` holds `vo.wav`, `facecam-part1.mp4` (both cut from `Taruns_recording/`), `broll-clean.mp4`, `drone.wav` and `sfx/*.mp3`.

## Media not in git

GitHub rejects files over 100 MB, and the renders can all be rebuilt, so `.gitignore` excludes all `*.mp4`, `*.mov`, `*.wav`, `*.blend` files, the blockout frame dumps, and the raw recording. To rebuild:

- **Animatics and b-roll:** `hyperframes render` in each project.
- **Blockout:** run `scene.py` through Blender, as described above.
- **`vo.wav` and `facecam-part1.mp4`:** cut from the presenter's master recording, which is kept offline.
