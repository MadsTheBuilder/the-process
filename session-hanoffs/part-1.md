### What each frame contains

- **Panel (1216x684):** an SVG stick-figure scene with the environment, lighting arrows (3000K amber key, 6500K cool fill), rust focus rings and the camera move.
- **Panel overlays:** a label row with lens, height and move, and a top-down camera plan.
- **Side card:** camera, lighting, environment, characters and a direction note, plus two reference thumbnails.
- **Below the panel:** the narration line, with a speaker tag (VO, FATHER, SELLER or VO + SELLER) and an English translation.
- **Timeline strip:** sequence bars and shot cells, with each cell's top border coloured by shot type.
- **Header:** the scene slug changes with each sequence. It reads Sc.01 for the mela, Sc.02 for the balloon seller, and "narrator set" for SEQ 6.

## 4. How to work on it

Run these from inside `red-balloon-part1/`:

```bash
npx --yes hyperframes@0.8.91 check                                  # must be 0 errors (3 lint warnings about file size and track density are known and fine)
npx --yes hyperframes@0.8.91 snapshot --at 8,30.9,54 --no-end       # stills in snapshots/, plus contact sheets
npx --yes hyperframes@0.8.91 render -o renders/<name>.mp4 --fps 25  # about 3.5 min for the full 1:42
npx --yes hyperframes@0.8.91 preview --background                   # Studio at http://localhost:3002/#project/red-balloon-part1
```

**Timing is now driven by the data:**

- Shot start times are computed from each `dur` in `SHOTS`.
- The strip, the sequence bars, the timecode and the total length all follow from those durations.
- The static `<section>` tags must match: each needs the same `data-start` and `data-duration`, and `#root` and `#chrome` need the total `data-duration`. If they disagree, the script throws an error and the render fails. That is deliberate.

**To retime or add a shot:**

1. Change or add the shot's `dur` in `SHOTS`.
2. Add a `scenes.sXX` function if the shot is new.
3. Update the `<section>` tags and the root and chrome durations to match.
4. Put its tweens at `A.sXX + offset`.

## 5. Gotchas

- **Layout check fails on overlaps.** `check` fails when SVG labels overlap the HUD row, which sits at about y 52–85 at the top left of the panel. It also fails on anything that overlaps the camera plan box, at about x 952–1202, y 14–186. Keep labels out of those zones.
- **Studio edits the file.** While a preview runs, Studio adds `data-hf-id` attributes to `index.html`. That is harmless.
- **Selector lint error.** `lint` rejects `querySelector` with a template literal. Use `getElementById(id).querySelector(".x")`.
- **`arrow()` argument order.** The signature is `(x1, y1, x2, y2, colour, markerId, text, opts)`. Leaving out the marker id produces NaN SVG.
- **Python for PDF work.** PyMuPDF (`fitz`) and PIL are installed in the system Python at `C:\Users\madhu\AppData\Local\Microsoft\WindowsApps\PythonSoftwareFoundation.Python.3.12_qbz5n2kfra8p0\python.exe`. The `python` on the Bash PATH doesn't have them.
- **Board crops.** Book boards sit at fixed PDF coordinates in points on a 720x864 page:
  - A: x 42–352, y 338–514
  - B: x 368–678, y 338–514
  - C: x 42–352, y 578–754
  - D: x 368–678, y 578–754
- **Blocked deletions.** `rm` with a relative glob after `cd` gets blocked by the safety check. Use absolute paths.
